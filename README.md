# TraeTools-Android

> 极简 Trae 签到助手：本地一键签到 · 云端自动托管 · 多账号切换 · 多渠道推送
> **纯 Android 手机端（APK）** —— 本仓库不再构建或发布任何 Windows 版本

> ⚠️ 2026-10-15 起本仓库收敛为**单一 Android 目标**：`net10.0-windows` 目标、WinForms/WebView2
> 登录宿主、DPAPI 实现、托盘图标、单文件 exe 发布与相关 CI/发布作业**均已移除**，只产出 APK。
> 因此下文涉及 Windows 的说明一律以「已移除」理解；Android 端的能力见「平台能力对照」。

TraeTools-android 是对 **TRAE-Tools** 的重构安卓版，用 Avalonia 重写为现代化跨平台应用（.NET 10）。
**2.0 做了产品减法**：去除用量统计与繁复设置，界面收敛为**单页仪表盘**——本地签到、云端托管、最近记录三块，专注、清晰、一次点完。

> **2.0 极简重构（Less is More）**：原「仪表盘 / 用量统计 / 每日签到 / 账号切换 / 云端签到 / 设置」六页导航已合并为**单页 + 二级设置**；用量统计整体下线。已登录账号、签到历史与云端部署状态**完全保留**，升级后无需重新配置。

> **2.1 版本（多账号 · 多推送 · 可诊断）**：在保持单页仪表盘的前提下，把 2.0 减掉的多账号能力以更轻的形态加回——顶栏一个账号胶囊即可切换；同时补齐四种登录方式、七条推送渠道、完整日志页与全局深色模式。

> **2.2 版本（账号可控 · 数据可见 · 安全可查）**：账号不再只是「一个 Token 的容器」——可以为每个账号写**简介**、看**积分数据面板**、**自定义 16 位设备号**、按自己的节奏开**保活**；并新增**账号与本地安全检查**。同时修掉两个影响体验的问题：GitHub 授权按钮现在会**自动拉起手机浏览器**，顶栏账号下三角展开的是**账号列表**而不是把你带去登录页。

## 2.2.0 更新内容

| 能力 | 说明 |
|---|---|
| **账号简介** | 每个账号可写一段自由文本备注（如「主号 · 只用来跑代码」）。设置页账号卡片与顶栏账号列表都会显示；输入后自动保存（防抖落盘，无需点保存按钮） |
| **积分数据面板** | 选中账号即出数：**剩余积分 / 已消耗 / 累计获得 / 总额度 / 今日获得 / 连续签到 / 签到天数 / 最近签到**，外加会员·学生·今日是否已签·Token 有效期的状态串。本地统计来自签到数据库（离线可看），额度三块来自云端接口，点「刷新数据」即时拉取 |
| **自定义 16 位设备号** | 设备号输入框支持**手动填写 + 随机生成 + 保存**，实时校验「必须 16 位数字」与「不得与其它账号重复」（重复会触发风控 9074），不合法时给出明确原因 |
| **账号保活** | 每个账号独立的**开关 + 间隔（5–1440 分钟）**。到点用会话 Cookie 静默换新 Token，顺带刷新积分与资料；只探测不签到，不影响「今日是否已签」。支持「立即保活」。⚠️ 与自动签到一样仅在软件运行期间有效，无人值守请用云端签到 |
| **安全检查** | 一键审计 8 项：配置加密状态、平台加解密自检、**明文敏感字段残留**、设备号合规与重复、Token/会话有效期、保活覆盖、数据目录私有性、**日志是否泄漏完整凭证**。结论按「风险 → 警告 → 通过」排序，只列字段名不显示内容，全程本地判断、不上传 |
| **GitHub 授权自动开浏览器**（修复） | 「授权 GitHub」现在会直接拉起系统默认浏览器打开授权页。本机（Android）侧按 Activity → Application 上下文 → 系统选择器三级回退；**任一环节失败都会写进日志**（`日志 → 全部 → browser`），不再出现「点了没反应也查不到原因」 |
| **顶栏账号下三角改为展开账号列表**（修复） | 过去只有一个账号时点下三角会被直接带去设置页，感觉像「被强行拉去登录」。现在**始终展开账号列表**，列表底部固定提供「添加账号 / 管理账号」入口 |
| **Android 凭证解密失败**（修复，重要） | 旧版把「跨平台密文互不通用」这条判断写在了共享封装里，而 **Android 自己的密文正是 `and-v1:` 前缀**，于是被自己的规则拦下——Android 上**所有**加密字段都解不开：Token 每次启动即丢、**设备号退化成密文被当作设备号发出**，直接触发风控 `9074 当前参与用户太多`。现已把该判断下移到 Windows 实现内部，并加了自愈：运行时发现设备号不是 16 位数字就自动换发新号（换号后需重新「云端部署」） |

## 功能特性

- **本地一键签到**：打开即点，秒签；多账号时出现极简账号勾选行（勾谁签谁，自动签到与此一致）
- **多账号管理**：顶栏胶囊一键切换当前账号；账号资料、Token、设备号彼此独立，切换后自动重载
- **云端托管签到（永不掉线）**：一键把签到任务部署到你自己的 GitHub fork（GitHub Actions 每天 08:00 运行），无需电脑/手机开机；部署进度以竖向流程清单可视化
- **四种登录方式**：内嵌浏览器 / 剪贴板智能识别 / 读取本机 TRAE 客户端 / 手动粘贴（含会话 Cookie 导入）
- **七条推送渠道**：飞书、邮箱 SMTP（可自定义端口）、通用 Webhook、钉钉（加签）、企业微信、Telegram、系统本地通知
- **日志页**：最近日志与历史归档日志双视角，自动滚动可开关
- **深色模式**：跟随系统 / 浅色 / 深色 三态可选，界面与对话框全局适配
- **账号备份**：口令加密导出 / 导入，跨设备迁移账号
- **云端状态徽章**：顶栏常驻「🟢 云端运行中 / 🟡 待部署 / 🔴 云端未部署」，点击展开云端详情
- **账号资料**：展示每个账号的昵称 / 脱敏手机号 / 头像 / 学生认证徽章（在设置中管理）
- **应用更新（不强制）**：内置检查更新，发现新版仅提示；仅提示并引导至 GitHub 下载页手动安装新版 APK（不自动安装）——不强制，可随时取消

## 快速开始

### 方式一：直接使用

在 [Releases](https://github.com/akexin/TraeTools-Android/releases) 下载最新版：

| 平台 | 产物 | 说明 |
|---|---|---|
| Android | `TraeTools-Android.apk` | 支持 Android 8.0（API 26）及以上，下载后需允许「安装未知来源应用」 |

> Release 里现在**只有 APK 一个资产**（含签名三方案 v1/v2/v3 与证书指纹门禁）。

### 方式二：源码编译

需要 **.NET 10 SDK** 与 Android workload：

```bash
git clone https://github.com/akexin/TraeTools-Android.git
cd TraeTools-Android

# 首次需安装 Android workload（约 1.5GB）
dotnet workload install android

# 本地构建 / 打包（项目为单一 net10.0-android 目标，无需 -f 与 EnableWindowsTargeting）
dotnet build TraeTools.csproj -c Release
dotnet publish TraeTools.csproj -c Release -o publish-android
# 产物：publish-android/cn.akexin.traetools-Signed.apk
```

## 使用指南

### 1. 添加 / 登录账号

`设置 → 账号管理 → + 添加` 打开登录窗口，共提供四种方式（按平台自动给出可用项）：

| 方式 | 平台 | 说明 |
|---|---|---|
| 从剪贴板识别导入 | ✅ 首选 | 先在浏览器登录并复制凭证，再点此按钮；自动判定是 Token 还是会话 Cookie，并剥掉 `X-Cloudide-Session=`、`Authorization:`、成对引号、换行等外壳 |
| 手动粘贴 | ✅ 可用 | 粘贴后保存，可在下拉框指定内容类型（自动识别 / Token / 会话 Cookie） |
| 打开浏览器登录 | ✅ 可用 | 用系统默认浏览器打开 trae.cn 完成登录，再回到本页粘贴凭证 |
| 读取本机 TRAE 客户端 | ⚠️ 视设备而定 | 该方式扫描的是桌面客户端的 `%APPDATA%` 数据目录，手机上通常不存在，会给出明确提示 |
| 内嵌浏览器自动登录 | ❌ 已随 Windows 目标移除 | 依赖 WinForms + WebView2，仅桌面端可用；Android 上该按钮会提示改用上面的方式 |

- 粘贴**会话 Cookie**（`X-Cloudide-Session` 的值）时，程序会用它换取 Token，并保留会话用于后续静默续期——这是手机端最省事的方式。
- 登录态约 14 天，失效可一键静默续期。
- 手机端流程：`+ 添加` → 「打开浏览器登录」→ 在浏览器登录 trae.cn → 复制凭证 → 回到 App 粘贴。

### 2. 切换当前账号

- **顶栏胶囊**：点标题右侧的账号胶囊展开账号列表，点选即切换（当前账号带勾选标记，已签到今日的账号带 ✓）。副标题优先显示你为该账号写的**简介**，没写时显示脱敏手机号。
- 列表**始终可展开**（哪怕只有一个账号），底部固定有「添加账号 / 管理账号」入口，直达设置页的账号管理区。
- **设置页**：`设置 → 账号管理` 中直接点选某一行账号同样完成切换，选中后下方会展开该账号的**详情面板**（简介、积分数据、设备号、保活）。
- 切换后签到引擎、首页状态与云端状态会整体重载，无需重启。

### 3. 本地签到

首页「本地签到」卡片点「一键签到」即可；多个账号时卡片内会出现勾选行，勾选即为要签的账号。也可在设置中开启「每日自动签到」，到点自动执行。每次结果会写入本地历史，并出现在首页「最近记录」。

> Android 端自动签到仅在 App 运行期间有效；需要无人值守签到请使用「云端签到」（GitHub Actions 每日 08:00 执行，与手机状态无关）。

### 4. 云端签到（部署到 GitHub Actions）

1. 首页「云端自动签到」卡片点击主按钮（首次为「授权 GitHub」；设备码授权，无需密码，仅需 repo 权限）
2. 再次点击（此时为「一键部署到云端」）：程序自动 fork 本仓库 → 写入每个账号的 `TRAE_SESSION` / `TRAE_DEVICE_ID` secret → 启用并触发验证运行；部署进度在卡片内的竖向流程清单上实时更新
3. 验证成功即生效：**每天北京时间 08:00** 自动签到，即使本机关机也不中断；顶栏徽章变为 🟢 云端运行中

部署原理：fork 仓库中的 `.github/workflows/checkin.yml` 定时运行 `checkin.py`，脚本用 `X-Cloudide-Session` 换取新 JWT 后调用签到接口（仅依赖 Python 标准库）。

### 5. 推送通知

`设置 → 推送通知`，最上方是总开关（签到完成后是否推送），下面每个渠道各有独立开关与配置。配好后点「测试全部已启用渠道」可一次性验证；邮箱渠道还可在展开区内单独点「发送测试邮件」。

| 渠道 | 需要填写 | 备注 |
|---|---|---|
| 飞书 | Webhook 地址 | 沿用 2.0 的配置 |
| 邮箱 SMTP | 服务器、端口、安全方式、用户名、密码/授权码、发件人、收件人 | 465 走隐式 TLS、587 走 STARTTLS、25 为明文；国内邮箱（QQ/163 等）需填**授权码**而非登录密码 |
| 通用 Webhook | 地址、请求体模板、Content-Type | 模板中用 `{title}` / `{content}` 占位；一份配置即可兼容 Server酱、PushPlus、Bark 等 |
| 钉钉 | Webhook 地址、加签密钥（可选） | 机器人若启用「加签」必须填密钥，否则会被拒绝 |
| 企业微信 | Webhook 地址 | 群机器人地址已含 key，直接粘贴完整地址 |
| Telegram | Bot Token、Chat ID | `api.telegram.org` 在国内网络通常需代理，失败时会有明确提示 |
| 系统本地通知 | 无 | 走 Android 通知栏；Android 13+ 首次开启时会申请通知权限 |

> 各渠道**互不影响**：一个渠道配错不会阻断其它渠道，也不会影响签到本身；每个渠道的成败都会写进日志页。

### 6. 查看日志

点顶栏的日志图标进入（返回按钮回到首页）。

- **最近**：本次运行产生的日志，随写随到；顶部显示条数与「错误 N 警告 M」。可「复制最近」一次性取走全部内容用于排查。
- **全部**：磁盘上按模块 / 月份归档的历史日志（含崩溃日志），上方选文件、下方看内容；可单个删除，或「清空全部」。
- **自动滚动**：默认开启；**关闭后**新日志仍会进入列表，但视图停在当前位置——翻看早先记录时不会被不断涌入的新日志推着走。右上角开关即可切换，偏好会记住。

### 7. 账号备份（跨设备迁移）

`设置 → 账号备份`：

1. 填一个**至少 6 位**的口令（它用于加密备份文件，务必记住——口令丢了备份无法恢复）
2. 点「导出备份」：优先弹出系统保存框存成 `.json`；平台不支持文件选择器时自动退化为「复制到剪贴板」，由你自行粘贴保存
3. 在另一台设备上：「选择备份文件」或直接把备份内容粘贴到文本框 → 填同一口令 → 「导入账号」

备份文件用 PBKDF2-SHA256（20 万次）派生密钥 + AES-256-GCM 加密，因此**可以安全地经网盘 / 聊天工具传输**；也正是因为不依赖本机的 DPAPI / Keystore，它才能跨设备使用。导入采用合并策略：同一账号刷新凭证，新账号追加，**不会删除本地已有账号**。

### 8. 账号详情（简介 / 积分数据 / 设备号 / 保活）

`设置 → 账号管理`，在列表里点选一个账号，下方即展开该账号的详情面板：

**① 账号简介** — 一段自由文本（最多 200 字），例如「主号 · 只用来跑代码」。停手约 0.8 秒自动保存，无需点任何按钮；顶栏账号列表与账号卡片都会展示它。

**② 积分数据面板** — 选中即出数，不发网络请求：

| 指标 | 口径 |
|---|---|
| 剩余积分 | 云端额度接口汇总（`credits_limit − credits_amount`），点「刷新数据」更新 |
| 已消耗 | 各资格包 `usage.credits_amount` 之和 |
| 总额度 | 各资格包 `credits_limit` 之和 |
| 累计获得 | 本地签到数据库里该账号的历史签到积分之和 |
| 今日获得 / 连续签到 / 签到天数 / 最近签到 | 本地签到数据库（离线也能看） |

面板底部一行状态串汇总：会员与否、学生认证、今日是否已签、Token 有效至何时。

**③ 设备号（16 位数字）** — 可直接手填，也可「随机生成」，点「保存设备号」生效。输入时实时校验两项：**必须 16 位纯数字**、**不得与其它账号重复**（重复会被风控判成同一台设备，签到报「参与用户太多」）。修改后云端签到需重新「云端部署」同步。

**④ 保活** — 打开开关并设定间隔（5–1440 分钟，默认 60）后，程序会按该间隔用会话 Cookie **静默换新 Token**，顺带刷新积分与账号资料；也可点「立即保活」马上执行一次。

- 保活**只探测、不签到**，不会影响「今日是否已签到」的判定，也不会产生积分。
- 无论成败都会记录时间与原因（面板上直接能看到「最近 一次执行 + 结果」）。
- ⚠️ 与自动签到一样，保活**仅在软件运行期间有效**；需要无人值守请使用云端签到。

### 9. 安全检查

`设置 → 安全检查` → 「开始检查」。全程在本机判断，不联网、不上传、不修改任何数据，结论按「风险 → 警告 → 通过」排序，**只列字段名，绝不显示凭证内容**。

| 检查项 | 关注点 |
|---|---|
| 配置加密 | 凭证是否已用平台密钥加密（Android Keystore） |
| 加解密自检 | 当场做一次加密→解密往返，确认加密真的生效（不是原样写回） |
| 明文残留 | 直接读配置文件，核对 11 个敏感字段及其账号副本是否都是密文 |
| 设备号 | 是否 16 位数字、是否有两个账号共用同一个号 |
| 登录态有效期 | 解析 JWT 的 `exp`，区分「已过期但有 Cookie 可续期」「已过期且必须重登」「1 小时内过期」 |
| 保活覆盖 | 哪些账号还没开保活（未开时 Token 过期要等下次签到才续期） |
| 数据目录 | 配置是否落在用户私有目录内 |
| 日志脱敏 | 抽查最近日志文件，确认没有把完整 Token / 会话 Cookie 写进日志 |

## 常见问题

| 现象 | 说明 / 处理 |
|---|---|
| 签到提示「当前参与用户太多」 | Trae 风控：同设备/网络频繁请求触发。建议错开 08:00 高峰、减少账号数、不同账号用独立设备号。**若 2.2.0 之前用过 Android 版**：日志里若看到 `DeviceId=and-v1:…`（密文被当成设备号），升级到 2.2.0 后设备号会自动修复，或在账号详情里点「随机生成」→「保存设备号」，然后重新「云端部署」 |
| 云端部署 HTTP 401 | GitHub 授权失效或权限不足：点「重新授权」；仍失败则自动删除旧 fork 重建 |
| 云端提示「未找到 workflow」 | 旧 fork 早于本仓库添加 checkin.yml：按提示一键「删除并重建 fork」即可自愈 |
| 签到 0 积分 | 当日已签过（重复签到不加分），或非会员当日基础 150 分已到账 |
| Token 失效 | 程序会用 `X-Cloudide-Session` 静默换新；彻底失效时提示重新登录 |
| Android 安装 APK 被拦截 | 系统设置中允许浏览器/文件管理「安装未知来源应用」后重试 |
| 邮箱推送失败，提示认证错误 | 国内邮箱几乎都需要填**授权码**（在邮箱网页端「设置 → 账户」中生成）而不是登录密码 |
| 切换账号后要重新登录 | 每个账号的 Token 各自独立；新加的账号需要单独登录一次，之后即可随意切换 |
| 「读取本机 TRAE 客户端」点了没反应 | 该方式扫描的是桌面客户端的数据目录，手机上通常不存在；请改用「从剪贴板识别」或手动粘贴 |
| Telegram 推送超时 | `api.telegram.org` 在国内网络通常不可直连，需自备代理 |
| 深色模式没有跟着系统变 | 主题是**三态**：`设置 → 主题模式` 选「跟随系统」才会随系统切换；选「浅色 / 深色」则为固定值 |
| 日志页一直往下跑，看不了上面的内容 | 关掉日志页右上角的「自动滚动」开关即可（偏好会记住） |
| 保活开着，Token 还是过期了 | 保活**只在软件运行期间**生效：进程被系统清理后即停止。请在系统设置里允许本应用后台运行，或改用云端签到（与本机状态无关） |
| 自定义设备号提示「与账号 X 重复」 | 每个账号必须用互不相同的 16 位数字设备号，点「随机生成」会自动避开已被占用的号 |
| 「授权 GitHub」没弹出浏览器 | 现在会自动拉起系统默认浏览器；若仍失败，到 `日志 → 全部 → browser` 看具体原因（Android 上会依次尝试 Activity → 应用上下文 → 系统选择器三级回退） |
| 积分面板的「剩余积分 / 已消耗 / 总额度」显示「—」 | 这三项来自云端额度接口，点面板里的「刷新数据」（或等一次保活 / 签到）后才有值；累计获得、签到天数等本地统计离线就能看 |
| 安全检查报「明文残留」 | 说明配置文件里对应字段还没加密。到设置页点一次「保存设置」即可触发重新加密落盘；若仍报，考虑「重置软件」后重新登录 |

> 云端签到凭证 `TRAE_SESSION` 有效期约 14 天，过期后请在软件内重新登录并重新部署。

## 开发者

- 技术栈：Avalonia 12 / .NET 10 / CommunityToolkit.Mvvm / Sodium.Core
- 目录：`ViewModels/` 页面逻辑、`Services/` 网络与领域服务（`Login/` 登录导入与备份、`Notify/` 推送渠道、`KeepAlive/` 账号保活、`Security/` 安全检查、`AppLog.cs` 统一日志）、`Views/` 界面、`Models/` 数据模型、`Platform/` 平台抽象（Keystore 加密、浏览器启动、崩溃日志等）
- 目标框架：**单一 `net10.0-android`**（APK）。本项目不产出桌面端产物；`net10.0-windows` 目标与桌面专属实现（WinForms/WebView2 登录宿主、DPAPI、托盘、单文件 exe 发布）已移除
- **主题**：`Styles/AppTheme.axaml` 用 `ThemeDictionaries` 提供 Light/Dark 两套令牌，界面一律用 `{DynamicResource XxxBrush}` 引用，不写死颜色；切换入口是 `App.ApplyThemeMode`
- **日志**：`Services/AppLog.cs` 为唯一写入点（内存环形缓冲 + 按月分文件落盘），格式 `[时间] [级别] [账号] 消息`，向后兼容旧格式。日志分类名决定归档文件名（`{category}_log_yyyyMM.txt`），新增分类无需改读取侧
- **保活**：`Services/KeepAlive/KeepAliveService.cs` 挂在 `MainView` 的 30 秒定时器上，与自动签到共用节拍；判定逻辑是 `TraeAccount.IsKeepAliveDue`，只换 Token 不 claim
- **安全检查**：`Services/Security/SecurityAudit.cs` 全部为本地只读判定，**报告只输出字段名与结论，绝不回显凭证内容**
- ⚠️ **XAML 注释里不能出现 `--`**：用 `----` 画分隔线会让 Avalonia 直接构建失败（`AVLN1001`），改用 `====`
- **本地静态检查**（`tools/`，无需装依赖，纯标准库）：`python tools/check_bindings.py`（校验全部 `{Binding}` 路径能否解析，本项目未启用编译绑定，这一步能提前拦下写错的属性名）、`python tools/lint_xaml_comments.py`（拦 `AVLN1001`）、`python tools/lint_cs.py`（括号配平与未闭合字符串）
- 行为默认不对外请求官方非公开接口之外的能力；用量/积分接口为逆向网页接口，字段随官方可能变化，代码均做容错解析
