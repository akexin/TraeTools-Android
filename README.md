# TraeTools-Android

> 极简 Trae 签到助手：本地一键签到 · 云端自动托管 · 多账号切换 · 多渠道推送
> 支持 **Windows 桌面端** 与 **Android 手机端**（APK）

TraeTools-android 是对 **TRAE-Tools** 的重构安卓版，用 Avalonia 重写为现代化跨平台应用（.NET 10）。
**2.0 做了产品减法**：去除用量统计与繁复设置，界面收敛为**单页仪表盘**——本地签到、云端托管、最近记录三块，专注、清晰、一次点完。

> **2.0 极简重构（Less is More）**：原「仪表盘 / 用量统计 / 每日签到 / 账号切换 / 云端签到 / 设置」六页导航已合并为**单页 + 二级设置**；用量统计整体下线。已登录账号、签到历史与云端部署状态**完全保留**，升级后无需重新配置。

> **2.1 版本（多账号 · 多推送 · 可诊断）**：在保持单页仪表盘的前提下，把 2.0 减掉的多账号能力以更轻的形态加回——顶栏一个账号胶囊即可切换；同时补齐四种登录方式、七条推送渠道、完整日志页与全局深色模式。

## 2.1.0 更新内容

| 能力 | 说明 |
|---|---|
| **多账号切换** | 顶栏账号胶囊（头像首字 + 当前账号名）一键展开账号列表，点选即切换；设置页账号列表同样支持点选切换。切换后签到引擎、仪表盘与云端状态整体重载 |
| **四种获取登录态的方式** | ① 内嵌浏览器自动登录（Windows）② 从剪贴板智能识别导入（自动区分 Token / 会话 Cookie，自动剥掉 `X-Cloudide-Session=`、`Authorization:`、引号与换行等外壳）③ 读取本机 TRAE 客户端（Windows，免手动复制）④ 手动粘贴（可选指定内容类型，手机端主路径） |
| **会话 Cookie 导入** | 直接粘贴 `X-Cloudide-Session` 即可，程序自动换取 Token 并保留会话用于后续静默续期 |

| **七条推送渠道** | 飞书（沿用）、**邮箱 SMTP**（可自定义服务器与端口，支持 465 隐式 TLS / 587 STARTTLS / 25 明文）、**通用 Webhook**（兼容 Server酱 / PushPlus / Bark，请求体模板可改）、**钉钉**（支持加签）、**企业微信**、**Telegram Bot**、**系统本地通知**。渠道间互不影响，单个失败不阻断其它 |
| **日志页** | 顶栏日志图标进入。分「最近」（本次运行实时日志，随写随到）与「全部」（按模块/月份归档的历史文件 + 崩溃日志，可逐文件查看、删除、清空）两个视角；**自动滚动可开关**（关掉后翻看历史不会被新日志推着走） |
| **深色模式全局适配** | 主题改为**三态**（跟随系统 / 浅色 / 深色），全部界面与对话框统一走主题令牌 |

> **2026-10 客户端合并公告**：字节跳动已于 2026-10-09 将 TraeWork 与 TraeCode 合并为统一的 **TRAE** 客户端（Agent / IDE 双模式），TraeWork 于 2026-10-23 停服。本工具已同步适配：设备号解析、客户端进程/目录探测均覆盖新旧名称（TRAE / TRAE CN / TRAE SOLO CN），老用户升级客户端后无需任何操作。

## 功能特性

- **本地一键签到**：打开即点，秒签；多账号时出现极简账号勾选行（勾谁签谁，自动签到与此一致）
- **多账号管理**：顶栏胶囊一键切换当前账号；账号资料、Token、设备号彼此独立，切换后自动重载
- **云端托管签到（永不掉线）**：一键把签到任务部署到你自己的 GitHub fork（GitHub Actions 每天 08:00 运行），无需电脑/手机开机；部署进度以竖向流程清单可视化
- **四种登录方式**：内嵌浏览器 / 剪贴板智能识别 / 读取本机 TRAE 客户端 / 手动粘贴（含会话 Cookie 导入）
- **七条推送渠道**：飞书、邮箱 SMTP（可自定义端口）、通用 Webhook、钉钉（加签）、企业微信、Telegram、系统本地通知
- **日志页**：最近日志与历史归档日志双视角，自动滚动可开关
- **深色模式**：跟随系统 / 浅色 / 深色 三态可选，界面与对话框全局适配
- **账号备份**：口令加密导出 / 导入，跨设备迁移账号
- **云端状态徽章**：顶栏常驻「🟢 云端运行中 / 🟡 待部署 / 🔴 云端未部署」，点击展开云端详情
- **账号资料**：展示每个账号的昵称 / 脱敏手机号 / 头像 / 学生认证徽章（在设置中管理）
- **应用更新（不强制）**：内置检查更新，发现新版仅提示；Windows 端经用户确认后才下载并后台替换，Android 端仅引导至下载页手动安装——均不强制，可随时取消

## 快速开始

### 方式一：直接使用

在 [Releases](https://github.com/akexin/TraeTools-Android/releases) 下载最新版：

| 平台 | 产物 | 说明 |
|---|---|---|
| Windows | `TraeTools.exe` / `TraeTools-win-x64.zip` | 单文件自包含，无需安装 .NET 运行时 |
| Android | `TraeTools-Android.apk` | 支持 Android 8.0（API 26）及以上，下载后需允许「安装未知来源应用」 |

> Android 版与 Windows 版数据相互独立（加密机制不同），账号需在手机端重新登录一次。

### 方式二：源码编译

需要 **.NET 10 SDK**（Android 目标需额外安装 workload）：

```bash
git clone https://github.com/akexin/TraeTools-Android.git
cd TraeTools-Android

# Windows 桌面版（多目标项目须显式指定 -f）
dotnet build -c Release -f net10.0-windows

# Android 手机版（首次需安装 Android workload，约 1.5GB）
dotnet workload install android
dotnet publish TraeTools.csproj -c Release -f net10.0-android -o publish-android
# 产物：publish-android/cn.akexin.traetools-Signed.apk

# 非 Windows 系统（Linux/macOS）构建 Android 时需追加 -p:EnableWindowsTargeting=true
# （多目标项目还原会一并还原 net10.0-windows，需允许下载 Windows 目标包）
```

## 使用指南

### 1. 添加 / 登录账号

`设置 → 账号管理 → + 添加` 打开登录窗口，共提供四种方式（按平台自动给出可用项）：

| 方式 | 平台 | 说明 |
|---|---|---|
| 内嵌浏览器自动登录 | Windows | 手机号 + 验证码登录后自动读取凭证并保存，无需手工复制 |
| 从剪贴板识别导入 | 全平台 | 先复制凭证再点此按钮；自动判定是 Token 还是会话 Cookie，并剥掉 `X-Cloudide-Session=`、`Authorization:`、成对引号、换行等外壳 |
| 读取本机 TRAE 客户端 | Windows | 直接扫描本机 TRAE 数据目录（`%APPDATA%\TRAE*\User\`、`Local Storage\leveldb`）提取登录态，全程只读 |
| 手动粘贴 | 全平台（手机端主路径） | 粘贴后保存，可在下拉框指定内容类型（自动识别 / Token / 会话 Cookie） |

- 粘贴**会话 Cookie**（`X-Cloudide-Session` 的值）时，程序会用它换取 Token，并保留会话用于后续静默续期——这是手机端最省事的方式。
- 登录态约 14 天，失效可一键静默续期。
- 手机端流程：`+ 添加` → 「打开浏览器登录」→ 在浏览器登录 trae.cn → 复制凭证 → 回到 App 粘贴。

### 2. 切换当前账号

- **顶栏胶囊**：点标题右侧的账号胶囊展开账号列表，点选即切换（当前账号带勾选标记，已签到今日的账号带 ✓）。
- **设置页**：`设置 → 账号管理` 中直接点选某一行账号同样完成切换。
- 只有一个账号时点击胶囊会直接跳到账号管理页。
- 切换后签到引擎、首页状态与云端状态会整体重载，无需重启。

### 3. 本地签到

首页「本地签到」卡片点「一键签到」即可；多个账号时卡片内会出现勾选行，勾选即为要签的账号。也可在设置中开启「每日自动签到」，到点自动执行。每次结果会写入本地历史，并出现在首页「最近记录」。

> Android 端自动签到仅在 App 运行期间有效；需要无人值守签到请使用「云端签到」（GitHub Actions 每日 08:00 执行，与手机状态无关）。

### 4. 云端签到（部署到 GitHub Actions）

1. 首页「云端自动签到」卡片点击主按钮（首次为「授权 GitHub」；设备码授权，无需密码，仅需 repo 权限）
2. 再次点击（此时为「一键部署到云端」）：程序自动 fork 本仓库 → 写入每个账号的 `TRAE_SESSION` / `TRAE_DEVICE_ID` secret → 启用并触发验证运行；部署进度在卡片内的竖向流程清单上实时更新
3. 验证成功即生效：**每天北京时间 08:00** 自动签到，即使本机关机也不中断；顶栏徽章变为 🟢 云端运行中

部署原理：fork 仓库中的 `.github/workflows/checkin.yml` 定时运行 `checkin.py`，脚本用 `X-Cloudide-Session` 换取新 JWT 后调用签到接口（仅依赖 Python 标准库）。

### 5. 推送通知

`设置 → 推送通知`，最上方是总开关（签到完成后是否推送），下面每个渠道各有独立开关与配置。配好后点「测试全部已启用渠道」可一次性验证；邮箱渠道还可在展开区内单独点「发送测试邮件」。

| 渠道 | 需要填写 | 备注 |
|---|---|---|
| 飞书 | Webhook 地址 | 沿用 2.0 的配置 |
| 邮箱 SMTP | 服务器、端口、安全方式、用户名、密码/授权码、发件人、收件人 | 465 走隐式 TLS、587 走 STARTTLS、25 为明文；国内邮箱（QQ/163 等）需填**授权码**而非登录密码 |
| 通用 Webhook | 地址、请求体模板、Content-Type | 模板中用 `{title}` / `{content}` 占位；一份配置即可兼容 Server酱、PushPlus、Bark 等 |
| 钉钉 | Webhook 地址、加签密钥（可选） | 机器人若启用「加签」必须填密钥，否则会被拒绝 |
| 企业微信 | Webhook 地址 | 群机器人地址已含 key，直接粘贴完整地址 |
| Telegram | Bot Token、Chat ID | `api.telegram.org` 在国内网络通常需代理，失败时会有明确提示 |
| 系统本地通知 | 无 | Windows 显示在主窗口右下角；Android 走通知栏，13+ 首次开启时会申请通知权限 |

> 各渠道**互不影响**：一个渠道配错不会阻断其它渠道，也不会影响签到本身；每个渠道的成败都会写进日志页。

### 6. 查看日志

点顶栏的日志图标进入（返回按钮回到首页）。

- **最近**：本次运行产生的日志，随写随到；顶部显示条数与「错误 N 警告 M」。可「复制最近」一次性取走全部内容用于排查。
- **全部**：磁盘上按模块 / 月份归档的历史日志（含崩溃日志），上方选文件、下方看内容；可单个删除，或「清空全部」。
- **自动滚动**：默认开启；**关闭后**新日志仍会进入列表，但视图停在当前位置——翻看早先记录时不会被不断涌入的新日志推着走。右上角开关即可切换，偏好会记住。

### 7. 账号备份（跨设备迁移）

`设置 → 账号备份`：

1. 填一个**至少 6 位**的口令（它用于加密备份文件，务必记住——口令丢了备份无法恢复）
2. 点「导出备份」：优先弹出系统保存框存成 `.json`；平台不支持文件选择器时自动退化为「复制到剪贴板」，由你自行粘贴保存
3. 在另一台设备上：「选择备份文件」或直接把备份内容粘贴到文本框 → 填同一口令 → 「导入账号」

备份文件用 PBKDF2-SHA256（20 万次）派生密钥 + AES-256-GCM 加密，因此**可以安全地经网盘 / 聊天工具传输**；也正是因为不依赖本机的 DPAPI / Keystore，它才能跨设备使用。导入采用合并策略：同一账号刷新凭证，新账号追加，**不会删除本地已有账号**。

## 常见问题

| 现象 | 说明 / 处理 |
|---|---|
| 签到提示「当前参与用户太多」 | Trae 风控：同设备/网络频繁请求触发。建议错开 08:00 高峰、减少账号数、不同账号用独立设备号 |
| 云端部署 HTTP 401 | GitHub 授权失效或权限不足：点「重新授权」；仍失败则自动删除旧 fork 重建 |
| 云端提示「未找到 workflow」 | 旧 fork 早于本仓库添加 checkin.yml：按提示一键「删除并重建 fork」即可自愈 |
| 签到 0 积分 | 当日已签过（重复签到不加分），或非会员当日基础 150 分已到账 |
| Token 失效 | 程序会用 `X-Cloudide-Session` 静默换新；彻底失效时提示重新登录 |
| Android 安装 APK 被拦截 | 系统设置中允许浏览器/文件管理「安装未知来源应用」后重试 |
| Android 与 Windows 账号不互通 | 两端加密机制不同（DPAPI / Keystore），数据独立，需分别登录；可用「账号备份」导出后在另一端导入 |
| 邮箱推送失败，提示认证错误 | 国内邮箱几乎都需要填**授权码**（在邮箱网页端「设置 → 账户」中生成）而不是登录密码 |
| 切换账号后要重新登录 | 每个账号的 Token 各自独立；新加的账号需要单独登录一次，之后即可随意切换 |
| 找不到「读取本机 TRAE 客户端」按钮 | 该方式仅 Windows 可用；未装客户端或客户端未登录时也会给出明确提示 |
| Telegram 推送超时 | `api.telegram.org` 在国内网络通常不可直连，需自备代理 |
| 深色模式没有跟着系统变 | 主题是**三态**：`设置 → 主题模式` 选「跟随系统」才会随系统切换；选「浅色 / 深色」则为固定值 |
| 日志页一直往下跑，看不了上面的内容 | 关掉日志页右上角的「自动滚动」开关即可（偏好会记住） |

> 云端签到凭证 `TRAE_SESSION` 有效期约 14 天，过期后请在软件内重新登录并重新部署。

## 开发者

- 技术栈：Avalonia 12 / .NET 10 / CommunityToolkit.Mvvm / Sodium.Core / WebView2（Windows）
- 目录：`ViewModels/` 页面逻辑、`Services/` 网络与领域服务（`Login/` 登录导入与备份、`Notify/` 推送渠道、`AppLog.cs` 统一日志）、`Views/` 界面、`Models/` 数据模型、`Platform/` 跨平台抽象（DPAPI/Keystore、浏览器启动等）
- 多目标：`net10.0-windows`（WinExe 单文件）与 `net10.0-android`（APK），平台差异集中在 `Platform/` 与 `#if ANDROID` 条件编译
- **主题**：`Styles/AppTheme.axaml` 用 `ThemeDictionaries` 提供 Light/Dark 两套令牌，界面一律用 `{DynamicResource XxxBrush}` 引用，不写死颜色；切换入口是 `App.ApplyThemeMode`
- **日志**：`Services/AppLog.cs` 为唯一写入点（内存环形缓冲 + 按月分文件落盘），格式 `[时间] [级别] [账号] 消息`，向后兼容旧格式
- 行为默认不对外请求官方非公开接口之外的能力；用量/积分接口为逆向网页接口，字段随官方可能变化，代码均做容错解析
